## Configuração do Gateway no EasyPanel

Variáveis específicas do Helena; não reutilizar tokens amplos de outros módulos:

```dotenv
HELENA_MEDIA_PROVIDER=supabase
HELENA_R2_ACCOUNT_ID=ae2b5f97708d13fa7e187cb470aafc40
HELENA_R2_BUCKET=helena-media
HELENA_R2_ACCESS_KEY_ID=<preencher diretamente no EasyPanel>
HELENA_R2_SECRET_ACCESS_KEY=<preencher diretamente no EasyPanel>
HELENA_MEDIA_LEGACY_READ=true
```

Criar credencial de **Object Read & Write**, limitada exclusivamente a **helena-media**. As duas chaves S3 devem ficar somente no servidor; não em `VITE_*`, no Git, nas memórias ou no chat. O navegador recebe apenas URLs temporárias de um único objeto, válidas por cinco minutos. Não precisa de acesso administrativo à conta nem de domínio público.

## Ativação e verificação

1. Instalar a versão do Gateway que contém `media-storage.mjs` e o script de migração. O padrão ainda é `supabase`, para não cortar imagens antes da configuração.
2. Instalar `hermes_visual.py` atualizado no runtime já existente do Hermes, com backup e sem reiniciar tarefas/receipts. Ele aceita somente o endpoint R2 desta conta, deste bucket e do próprio job; mantém compatibilidade com o upload legado.
3. Preencher as duas chaves S3 diretamente nas variáveis do Gateway e salvar/reimplantar.
4. No console do serviço Gateway, executar primeiro:

   ```sh
   node scripts/migrate-media-r2.mjs
   ```

   O modo padrão inventaria, lê os arquivos originais e calcula hashes sem escrever imagens no R2.

5. Conferido o inventário, executar:

   ```sh
   node scripts/migrate-media-r2.mjs --apply
   ```

   Cada objeto é copiado sem sobrescrever, relido do R2 e comparado por SHA-256. O script é retomável: conteúdo idêntico é aceito; conteúdo diferente no destino interrompe esse item. O manifesto em `/tmp/helena-media-r2-manifest.json` contém caminhos/hashes e contagens, sem credenciais ou URLs assinadas. Copiar esse manifesto para o checkpoint operacional antes de recriar o container. Originais não são apagados. Arquivos fora dos dois namespaces autorizados ou acima de 5 MB são marcados como falha e devem ser conferidos.

6. Só após confirmar `failed=0` e a quantidade esperada, definir `HELENA_MEDIA_PROVIDER=r2`, salvar e implantar. Novas imagens não têm fallback de escrita; falha de R2 não envia ao Supabase silenciosamente.
7. Abrir logo e entrega reais no painel autenticado, testar upload e leitura/hash de uma imagem no R2 e revisão com pixels no Hermes. `/health` deve mostrar `media_storage.provider=r2`; isso sozinho não comprova upload ou migração.
8. A leitura legada continua disponível apenas quando o objeto não existe no R2. Erro de permissão/serviço não aciona fallback. A verificação de um upload novo exige que a imagem esteja no provedor ativo. Desligar `HELENA_MEDIA_LEGACY_READ` somente depois da conferência completa.

As imagens do frontend são abertas por URL assinada através do Gateway autenticado. Upload de logo passa pelo Gateway; não é necessário liberar CORS do R2 para PUT direto no navegador. O Hermes usa PUT assinado com `If-None-Match: *`, preservando versões anteriores. Usuário comum mantém acesso somente às empresas permitidas; envio de logo é exclusivo do fundador. Agentes mantêm a autorização existente por tarefa, responsável e revisor.
