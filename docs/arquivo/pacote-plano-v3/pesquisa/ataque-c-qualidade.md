# Red-team lens C: content quality and agent behavior (plano-rev80.md)

Basis: the plan (569 lines), the brief, and K1-K23 (not re-reported; flaws in their fixes are labeled fix-of-K#). "L<n>" = line n of plano-rev80.md. Hermes evidence is from the read-only source copy analise2/src/hermes-agent (read and grepped, never executed); Codex evidence from analise2/src/codex/codex-rs. Public pages are cited by URL. Statistics are my own binomial calculations.

Count: 20 holes (2 critical, 11 high, 6 medium, 1 low), most severe first.

## Holes

### C-1 · fix-of-K1: Hermes cuts every MCP result over 50,000 characters to a 1,500-character preview, so the agent never reads "a página inteira" · critical
- Scenario: Clara calls `ler_pagina` on a platform ToS or privacy page. The default `tool_budget.mcp_result_size_chars` is 50,000 (budget_config.py:20). A larger result is saved under `$HERMES_HOME/cache/spillover/` and the model receives a `<persisted-output>` block with the first 1,500 chars plus "Use the read_file tool with offset and limit" (tool_result_storage.py:264-300; applied in the agent loop at tool_executor.py:1120,1182,1207; a 200,000-char per-turn aggregate also exists, budget_config.py:14). `read_file` is not in her whitelist. The K1 snapshot holds the full text, so any real quote passes the check, but the opinion and the risk table rest on about 1.5K chars while the voice/image licence clause sits deep in a long ToS. Result: risk "baixo", quotes verified, nothing flagged.
- Why the plan misses it: "Pronto quando toda afirmação cita uma cláusula da página oficial aberta inteira." (L189); "na cópia da página que o agente leu" (L257).
- Fix: `ler_pagina` returns parts of at most about 20,000 chars ("parte i de n" plus a cursor) so spillover never fires; the server logs which parts it served; the generated profile also sets `tool_budget.mcp_result_size_chars` high as a seatbelt. Services that promise whole-page reading (Parecer de termos) require 100% of parts served; otherwise the card shows "leitura parcial: x de n partes" and gate 1 rejects.
- Proving test: fixture ToS of 300K chars with a unique clause at char 280K. A fake-endpoint run that reads all parts must cite it with coverage 100%; a run that stops after part 1 must be rejected; no captured request body may contain the string `<persisted-output>`.
- Phase: 2 (the tool), 3 (the coverage rule in the validator).

### C-2 · fix-of-K3: per-task profile copies break the shared ChatGPT login unless they borrow the root grant; test 2 may never exercise a refresh · critical
- Scenario: the generator builds a profile per task and, to authenticate it, copies auth.json (the natural reading of "cópia do perfil"). Codex refresh tokens are single-use with family revocation. Hermes shares one login safely only when the profile has no `providers.openai-codex` of its own and sits at `<root>/profiles/<name>`: the refresh then runs under the root's lock and rotates ROOT's file (auth_codex.py:174-212, comment at 184-185 "a profile copy would shadow root and disable the write-through"; 522-566; auth.py:509-518, 830-865; hermes_constants.py:216-232). With a copy, the rotated token dies with the deleted profile, root keeps the consumed token, the next task replays it, OpenAI revokes the family, and every agent stops until a manual device login; it recurs at each refresh. If the directory is not under a `profiles/` parent there is no root fallback and every task exits 1 "login required". Hermes' own `profile create --clone-all` strips copied grants for exactly this reason (profiles.py:1293-1298). Refresh happens only within 120 s of JWT expiry (auth_constants.py:93); I did not verify the access-token lifetime, so 48 h may contain zero refreshes.
- Why the plan misses it: "cada tarefa roda numa cópia do perfil gerada da ficha, conferida no início e apagada no fim" (L139); "usa o login pelo mesmo caminho que o teste 2 aprovou, nunca uma cópia solta" (L438); "Nenhum login derrubado" (L31).
- Fix: write the rule into the doc and the generator: per-task HERMES_HOME = `<HERMES_ROOT>/profiles/<run-id>` with NO auth.json and NO credential_pool; the only auth.json is the v2 root's (own device login, K3). The generated-profile contract check fails the build if either appears. Test 2 counts only if the root `last_refresh` changed at least twice while 3 or more tasks overlapped.
- Proving test: (a) negative control: a profile containing an auth.json copy is rejected by the contract check; (b) the 48 h run reports the `last_refresh` changes and zero relogin errors; if the token lifetime is longer than the window, extend the window or force expiry on a disposable token family.
- Phase: 0 (decide the layout), 2 (test 2).

### C-3 · `hermes -z` has no step limit: "limite de passos", "24 passos" and `--max-turns` are false for the command the plan uses · high
- Scenario: `-z` builds the agent without `max_iterations` (oneshot.py:577-599), so it is `sys.maxsize` (agent_init.py:2364; run_agent.py:241). `agent.max_turns` (default None) and `HERMES_MAX_ITERATIONS` are read by `hermes chat`, gateway and cron (cli_init_mixin.py:199-210; gateway/run.py:1609-1625; cron/scheduler.py:2431-2435) and never by oneshot. `--max-turns` exists on the `chat` subparser (_parser.py:290) and on the legacy `hermes-agent` runner, which needs `--api-key/--base-url`, cannot use the ChatGPT login and prints a banner (run_agent.py:1470-1535; legacy_cli.py:42-60). Loop guardrails are warn-only on platform `cli` and cap only built-in `web_search` and `delegate_task` (tool_guardrails.py:80-85, 301-305), not MCP tools. `run_budget_seconds` only injects a notice (conversation_loop.py:124-152). A looping agent therefore runs until the motor's wall-clock kill, burning the shared ChatGPT window (Plus Sol is estimated at 15 to 160 messages per 5 h, L38), and the failure type "Limite de passos" can never occur.
- Why the plan misses it: "limite de passos" (L21); "24 passos, 25 buscas, 8.000 caracteres" (L173); "Limite de passos | Divide a etapa ou dá mais passos uma vez" (L281); "(`--max-turns` e `--enabled-toolsets`)" (L536).
- Fix: put the cap where we own the code. The `helena_web` MCP server counts every tool call of the run, answers calls beyond the cap with "LIMITE: entregue agora", writes `limite_atingido` to its log and, after 3 refused calls, may SIGTERM its parent; the motor maps `limite_atingido` without delivery to the "Limite de passos" row. Also set `agent.run_budget_seconds` to about 80% of the motor timeout (advisory only). Rewrite L21, L173 and L536. The spike may instead test `hermes chat -q -Q --max-turns 24 --ignore-rules` (honors both caps and skips context files, cli_agent_setup_mixin.py:671,693-694) but it has no `--usage-file` and returns exit 1 for incomplete runs (cli_single_query.py:152-195).
- Proving test: a fake endpoint that answers every request with a tool call; the process must end by itself after cap+3 model requests and the motor must record "Limite de passos".
- Phase: 2.

### C-4 · fix-of-K13: exit code and stdout of `-z` cannot separate provider failures from agent failures, so "sem ação" and the format retry will misfile them · high
- Scenario: exit 0 = completed, including tool errors; 1 = exception around the run, written to stderr as `hermes -z: agent failed: ...` (expired login, a recorded quota cooldown at credential resolution; oneshot.py:320-322; auth_codex.py:655-666), or an empty answer (oneshot.py:340); 2 = failed, partial or not completed (oneshot.py:92-106); 130 = interrupt. In the exit-2 case stdout carries Hermes' own English explanation, for example "... rate-limited every one of N attempts ... Wait a minute and send /retry" (turn_recovery.py:1165-1305; oneshot.py:324-336). `failure_reason` is stamped on the result but is NOT in `--usage-file` (`_USAGE_KEYS`, oneshot.py:31-35). The same quota wall thus shows up as exit 1 on stderr or exit 2 on stdout. A motor that parses stdout first sees non-JSON, spends the single K13 retry (another model call during a quota wall), files it as "sem ação" or "formato errado" (agent fault), and three of those open the disjuntor on an innocent agent. That is the v1 mislabel again.
- Why the plan misses it: "O motor classifica cada falha pelos próprios sinais (código de saída, estado do provedor, erro do Gateway, veredito do validador)" (L291); "Uma execução que termina sem exatamente uma das 5 ações é a falha 'sem ação'" (L141); "Falha do próprio agente: só essa conta para o disjuntor" (L295).
- Fix: write the decision order into the engine spec. (1) Always run with `--usage-file`; exit other than 0, or `failed/partial/interrupted`, or `completed=false` means infrastructure class: never parse stdout as an answer, spend no attempt, capped retries, escalate to "Falha desconhecida" (L287) when no rule matches. (2) Only exit 0 with `completed` goes to the JSON parser; invalid JSON gets the one K13 retry (same profile, the K1 server in frozen mode, previous answer plus schema as input, counted against the same cap). (3) Substring matching on stderr/stdout ("re-authenticate", "rate-limit") only chooses the message shown to the founder.
- Proving test: simulator returns exhausted-429, 401, 5xx, truncated output, prose and valid-but-wrong JSON. The first four must never reach the parser, consume no attempt, leave the disjuntor unchanged and produce four distinct card messages; the last two cost exactly one retry each.
- Phase: 2.

### C-5 · launch-directory context files act as system-level instructions in `-z`, and `--ignore-rules` does not turn them off there · high
- Scenario: `-z` builds the agent with `skip_context_files=False` (oneshot.py:577-599). It loads, first match wins: `.hermes.md` (walking up to the git root), the AGENTS.md chain (git root down to cwd), CLAUDE.md, .cursorrules, under the header "The following project context files have been loaded and should be followed" (prompt_builder.py:1712-1747, 1852-1883; system_prompt.py:713-726). cwd is the launch directory because `terminal.cwd` is bridged to TERMINAL_CWD only in gateway/cron (runtime_cwd.py:1-8). The top-level `--ignore-rules` help promises to skip AGENTS.md and memory (_parser.py:202-203) but in `-z` the env var only gates `skills.auto_load` (system_prompt.py:322-340); `chat` maps it to `skip_context_files` and `skip_memory` (cli_agent_setup_mixin.py:693-694). The Hermes container WORKDIR is /opt/hermes (Dockerfile:178) whose AGENTS.md is an 11,952-byte contributor guide, and the plan's own repo will carry a maintainer manual (L379). Hermes hit the same bug in its kanban workers: "workers load the gateway's AGENTS.md" (kanban_db_dispatch.py:2893-2905). Result: every task prompt starts with developer instructions that contradict the ficha, plus thousands of wasted tokens.
- Why the plan misses it: "cada agente recebe só um pacote curto por tarefa: o card, o modelo do serviço, as 5 ações, e as lições e exemplos daquele serviço" (L137); cwd is never mentioned.
- Fix: spawn every task with cwd = a fresh empty directory outside any git repository AND env `TERMINAL_CWD` set to the same path; keep snapshots and the profile elsewhere (a snapshot named AGENTS.md in a reused cwd would become system authority on retry, a web page reaching the system prompt); pass an environment allowlist, not the engine's environment.
- Proving test: plant AGENTS.md, .hermes.md and CLAUDE.md containing a marker string in the engine's cwd, its git root and /opt/hermes; the request captured at the fake endpoint must not contain the marker.
- Phase: 2.

### C-6 · fix-of-K1: if the `helena_web` server is slow or broken, the agent runs with zero tools and exit 0 · high
- Scenario: `-t helena_web` is validated only against names in config.yaml (oneshot.py:144-211). Discovery is waited for at most 15 s (mcp_startup.py:154-163, 260-271, 303-319; config_defaults.py:539) and the agent is built anyway; there is no between-turns refresh in one-shot mode (cli_single_query.py:507); an unregistered toolset is skipped silently in quiet mode (model_tools.py:282-309). On the loaded 4-vCPU VPS a cold Python start can exceed 15 s, or the server can crash after a dependency change. The agent answers from memory and exits 0. For Clara and Ravi the quote check rejects and three rejections trip the disjuntor on an innocent agent; for Isabela and Caio nobody notices that the "pesquisa" never happened.
- Why the plan misses it: the ficha row "Busca e leitura de páginas" (L171) has no start check; only "Site ou ferramenta fora do ar" is handled (L283).
- Fix: the server writes a handshake record (`initialize` and `tools/list` served, timestamp) into the task directory; any ficha that lists tools requires it, otherwise the class is "ferramenta fora do ar" (no attempt consumed, 3 retries, then Helena, as in L283). The generated config raises `mcp_single_query_discovery_timeout` to 45 or more and uses an absolute `command` (no npx, no downloads).
- Proving test: a server command that exits at start, and one that sleeps 20 s then works; assert the classification, zero attempts consumed, disjuntor unchanged, and success for the slow one.
- Phase: 2.

### C-7 · prompt injection: the plan blocks database writes but not steering of content, links or "Perguntar"; L448 has no mechanism · high
- Scenario: a page the agent reads (a ToS, a blog about recruiting) holds visible or hidden text telling the model to recommend a signup link, to say a platform is safe, or to ask the founder to approve something. The agent puts the link in Entregar, or asks through Perguntar, which reaches him through Helena as a trusted card with options (L133). Hermes wraps `mcp_` results as untrusted data, but only as advice (tool_dispatch_helpers.py:467-468; its risk scan "never blocks"). Nothing says the engine knows the run read the web, so the sentence about "só pode entregar ou registrar falha" is a wish, not a rule.
- Why the plan misses it: "um texto plantado num site não consegue mexer no banco" (L20); "Quem lê páginas da internet só pode entregar ou registrar falha, para que um texto plantado num site não consiga mandar o agente fazer outra coisa" (L448).
- Fix: a taint rule in the motor driven by the server log: if the run called `buscar` or `ler_pagina`, only Entregar and Registrar falha are accepted (anything else is "formato errado"). Every URL in an output must be in {URLs fetched, final URL after redirects, plus URLs in the card input}; others render as plain text with a "link não conferido" badge. The server returns plain text only and drops zero-width and CSS-hidden text before it snapshots. Agent text is rendered as text, never markup.
- Proving test: a fixture page with injected instructions (visible and hidden) and a simulator that obeys them: the tainted Perguntar is rejected, the injected URL is badged, the hidden text is absent from the model's view.
- Phase: 2 (taint, URL list), 3 (the reviewer sees the flags).

### C-8 · valid-but-wrong deliveries pass gate 1: quote presence is not support · high
- Scenario: (a) the quote exists but is cut from "não concede licença", or belongs to a different clause than the claim; (b) an absence claim ("a página não menciona biometria") that presence cannot verify and that is false after a partial read (C-1) or on a JS shell or cookie wall (the plan handles only "site fora do ar", L283); (c) a quote from a mirror or look-alike domain; (d) normalization is unspecified: too loose (case, accents, punctuation stripped, 3-word quotes) lets paraphrases pass, too strict (NBSP, curly quotes, hyphenation, "...") bounces honest quotes into endless "devolvido ao autor"; (e) the reviewer's "prova" text is never verified; (f) a delivery says "já enviei o convite": the 5-action contract limits what agents DO, not what their text CLAIMS.
- Why the plan misses it: "Toda citação precisa existir, palavra por palavra, na cópia da página que o agente leu" (L257); "apontando a prova" (L258).
- Fix: define once: a quote is a contiguous span of one snapshot part, at least 12 words or a full sentence, matched after Unicode NFC and whitespace/quote-mark folding only. The card and the reviewer get the full sentence or paragraph around each quote, extracted by CODE from the snapshot. Absence claims are a typed field `nao_encontrado` with the search terms and the coverage percentage from the server log. The "fonte oficial" label requires the final host to be the input link's registrable domain. Reviewer proofs go through the same verifier. First-person past-tense forbidden verbs (enviei, contatei, cadastrei, paguei, publiquei, assinei) in a delivery cause rejection.
- Proving test: extend K9's planted set with negation flip, wrong clause, truncated sentence, look-alike domain and an absence claim after a partial read (all 5 must be rejected), plus NBSP and curly-quote variants (must pass).
- Phase: 3.

### C-9 · fix-of-K8: recomputing proves the arithmetic, not the inputs, so the card's "Números" will look verified · high
- Scenario: E1 is "10 pessoas × horas × US$0,50 em 3 cenários". The model picks hours per person, the USD to BRL rate (from memory), fees, taxes and the scenario spread; the code recomputes and agrees. The founder reads "Números" as fact. The US$0,50 he gave may also differ from the rate on the platform's own page.
- Why the plan misses it: "toda conta do Caio é refeita pelo código" (L257); "A conta do Caio é refeita pelo código, que é mais seguro do que um segundo revisor" (L50) removes the second look.
- Fix: every number in the template carries `origem` in {pedido do fundador, fonte citada (quote verified, with date), premissa do agente}; code rejects numbers without it. Exchange rates come only from a cited, dated source read through the server, or are typed by the founder. The card has a fixed box at the top, "Premissas que você precisa confirmar", listing every `premissa do agente` with the effect of plus or minus 20% computed by code, and prints under the table "Cálculo conferido pelo código; premissas NÃO conferidas".
- Proving test: an invented exchange rate with no origem is rejected; a source older than 7 days is flagged; consistent arithmetic on a wrong premise passes the code but must appear in the premissas box.
- Phase: 2 (the E1 skeleton is the first card).

### C-10 · fix-of-K18: a table of real articles checks existence, not currency, applicability or coverage · high
- Scenario: (a) an invented statute is rejected (good). (b) A real article used wrongly passes. (c) Text unchanged, meaning changed: the STF declared Marco Civil art. 19 partially unconstitutional on 26 Jun 2025 (Temas 533 and 987, 8 to 3; https://www.machadomeyer.com.br/pt/inteligencia-juridica/publicacoes-ij/direito-digital/stf-muda-regime-de-responsabilizacao-das-plataformas), so an opinion using the old meaning passes. (d) Outside the K18 scope but relevant to image, voice and recruiting: Lei 15.211/2025 ECA Digital, in force 17 Mar 2026 (https://www.poder360.com.br/poder-governo/eca-digital-entra-em-vigor-nesta-3a-feira-entenda-o-que-muda/); Lei 15.123/2025, 24 Apr 2025, penalty +50% when AI alters a woman's image or voice (https://www.migalhas.com.br/quentes/428991/lula-sanciona-lei-que-agrava-crime-contra-mulher-com-uso-de-ia). From my own knowledge, to confirm: CDC art. 37 (misleading ads, E3), CLT art. 3º (vínculo when pay is per hour), LGPD arts. 5º II, 11 (biometric/sensitive) and 33-36 (international transfer), Código Civil arts. 11-21 beyond art. 20, Lei 9.610/98 arts. 89-92 (interpreter rights, voice). (e) A citation outside the table has no defined outcome: rejecting loops, letting it pass defeats the check. (f) No mandatory-topic list, so a missing topic is invisible.
- Why the plan misses it: "todo artigo de lei citado é conferido numa tabela de artigos reais" (L257); the legal service is "checagem LGPD e direito de imagem" (L170).
- Fix: table rows = {lei, artigo, texto literal, data de consolidação, nota de jurisprudência}; the validator requires each cited article to carry a quote of the TABLE text. An out-of-table citation is accepted but badged "não conferido" on the card and counted in the status strip (C-13). Per-service "temas obrigatórios" (imagem, voz, dado biométrico/sensível, transferência internacional, menores, remuneração/vínculo, publicidade), each answered "coberto (cláusula citada)" or "não encontrado em n de n partes". Card header: "Conferido contra tabela de DD/MM/AAAA; não substitui advogado". Table refresh is a dated item in the maintainer manual.
- Proving test: an invented "Lei 14.999/2023 art. 7" is rejected; art. 19 cited without its jurisprudence note is flagged; an omitted mandatory topic is rejected; 5 real-but-misused articles are planted and the reviewer's measured miss rate is reported.
- Phase: 1 (topics approved with the roteiro), 3.

### C-11 · "sem promessa de ganho" (E3) is not enforceable as written, and the income numbers reach the writer · high
- Scenario: the next agent receives "o resumo e os campos" of earlier steps (L312). If E3 depends on E1, Isabela gets Caio's US$/R$ figures and writes "complemente sua renda", "ganhos por hora" or a money emoji. The "critério automático" (L258) is either an AI rubric item (misses paraphrases) or a keyword list (misses implication). The text goes to strangers in the founder's name (CDC art. 37 exposure, vínculo risk). He wrote the rule precisely so he would not have to police it.
- Why the plan misses it: "Cada restrição do seu pedido vira um critério automático." (L258).
- Fix: (1) data minimisation: E3's input contract lists exactly which fields it receives and excludes every monetary figure; (2) a code gate on the invitation body using an income lexicon (R$, US$, $, dólar, renda, ganho(s), ganhar, remunera*, pagamento, salário, lucro, comissão, "por hora", money emojis): reject on a hit, false positives are cheap; (3) a rubric item judged by Clara with explicit paraphrase examples; (4) the card prints the two verdicts separately: "Código: 0 termos de ganho (lista de N)" and "Clara: sem promessa implícita (julgamento)"; (5) the founder gate stays because the class is external.
- Proving test: 10 explicit, 10 implicit and 10 clean invitations. Code must block 10/10 explicit; Clara must catch at least 8/10 implicit; at most 1/10 clean false positives; report the interval.
- Phase: 1 (input contract), 3 (gate).

### C-12 · test 7 ("pelo menos 9" de 10) does not show the reviewer works · high
- Scenario: with 9/10 caught, the 95% one-sided lower bound on the catch rate is 61% (two-sided 56%). A reviewer whose true catch rate is 70% passes 15% of the time, one at 80% passes 38%. There are no clean controls, so a reviewer that rejects everything scores 10/10. The planted errors come from the same AI family that will review (L64 itself admits "Revisor no mesmo modelo do autor erra nos mesmos pontos"), and the test runs once, in Fase 3, not on each rubric or model change.
- Why the plan misses it: "O revisor pega pelo menos 9" (L36); the item is closed by "Erros plantados (teste 7)" (L64).
- Fix: 30 planted errors across 7 classes (fake quote, negation flip, wrong clause, wrong premise, outdated law, missing mandatory topic, income-promise paraphrase), taken from real failures where possible, plus 10 clean controls. Pass = at least 27/30 caught (lower bound 76%; a 70% reviewer passes 0.9%, an 80% reviewer 12%) and at most 2/10 clean rejected. Report per class; classes under target keep the founder in the loop. Rerun on every model or rubric change (Fase 4 gate).
- Proving test: the test itself, plus a reject-all stub and an approve-all stub, both of which must FAIL it.
- Phase: 3.

### C-13 · the final card can mislead a non-programmer even when every gate passed · high
- Scenario: (a) "Resposta em uma frase" is AI prose over E1 to E5; it can say "pronto para aprovar" while Clara flagged a high risk, a statute is "não conferido" or the page was read partially; only risks and open questions are forced into a fixed section by code (L335). (b) "confiança (alta, média ou baixa)" (L312) is the author's own estimate; displayed, it reads as verified. (c) Quotes stay in the original language and the Portuguese translation is a separate, unchecked field (L60); the translation is what he reads, and "perpetual, irrevocable, exclusive, sublicensable" are exactly the words that matter. (d) "Card pronto nunca usa informação velha" cannot be enforced by a DB constraint or a watchdog, which know nothing about the web; he can approve three days later after the ToS changed.
- Why the plan misses it: "Resposta em uma frase, em destaque." (L326); "Como o agente preenche campos e não desenha a página, o resultado sai organizado todas as vezes." (L320); "Card pronto nunca usa informação velha | Sim | Sim | Sim" (L237).
- Fix: a code-computed status strip above everything, with no AI involved: claims verified by code / judged by AI / unverified, highest risk, partial reading, statutes not checked, premissas pending, snapshot age, reviewer disagreements. A red strip suppresses the AI one-liner. Drop self-reported confidence, or label it "autoavaliação da IA". Show the original first and the translation second, labelled; side by side for high-risk clauses. At "Aprovar", the server re-fetches each source (plain GET, hash of normalized text) and warns "a página mudou desde a leitura em DD/MM", no AI.
- Proving test: a card with a planted red flag and an AI sentence "tudo certo" shows the red strip and no sentence. Readability check in Fase 1 on the real E1 card: a fresh reader answers 5 fixed questions (what do I decide, biggest risk, what is unverified, what do the numbers assume, what changed) and gets at least 4/5.
- Phase: 2 (data model), 3.

### C-15 · "segundo provedor configurado, testado e desligado": Hermes has no "off" for a configured fallback · medium

### C-16 · retry and auxiliary layers multiply model calls and hide failures from the motor · medium
- Scenario: inside one `-z` run Hermes retries each call 3 times (agent_init.py:1436-1439), then up to 5 recovery cycles with waits of 15, 30, 60, 60, 60 s for 5xx, overload and timeouts (turn_recovery_autorecover.py:1-30; agent_init.py:1443), and starts an auto-title model call for the run (title generation is on and platform `cli` is not excluded: title_generator.py:736-790; turn_context.py:187,239). On top, the motor retries (K13, 3 site tries, 2 review rounds). A provider outage can eat the whole task timeout invisibly (seen as a timeout, not a provider failure), and the title call spends quota on nothing and sends the prompt text one more time.
- Why the plan misses it: classification by "tempo máximo" (L141, L247) and retries owned by the motor (L282-287) assume one layer.
- Fix: generated config sets `agent.api_max_retries: 1`, `agent.auto_recovery_cycles: 0`, `auxiliary.title_generation.enabled: false`, `compression.enabled: false` (an overflow then fails fast with exit 2 and a `turn_exit_reason` starting `context_compression_`; map it to "leitura/entrega grande demais"), `memory.memory_enabled: false`, `memory.user_profile_enabled: false`, `auxiliary.background_review.enabled: false`, `curator.enabled: false`. DBOS owns backoff. Verify every key in the spike by counting captured requests.
- Proving test: a fake endpoint returning 503 makes the process exit within seconds after one request; a normal run produces exactly the expected number of requests (no title call).
- Phase: 2.

### C-17 · model swaps and regressions: the recorded model is the requested alias, and the swap gates disagree and have little power · medium
- Scenario: usage-file `model` is `agent.model` (turn_finalizer.py:700); `served_model` exists only from LiteLLM-style headers (served_model.py:1-12, 55-68) and is not in `_USAGE_KEYS`, so with the ChatGPT backend a silent provider-side change is invisible in the logs. The nightly "rodada curta" has no size, metric, threshold or action. The gate "empatar ou melhorar" on 20 cases lets a real drop from 80% to 70% pass 29% of the time and fails an unchanged model 42% of the time (independent binomial samples). Four statements about what a swap runs: 60 real rounds (L367, L487) versus the 20-case scoreboard (L418, L424). A `--model` alias that trips the startup cost or data-policy guard makes every task exit 1 with "Refusing this startup model override" (main.py:1191-1265), indistinguishable from a provider failure unless C-4's order is followed.
- Why the plan misses it: "O modelo real de cada execução fica registrado" (L367); "Só segue se empatar ou melhorar." (L418).
- Fix: one swap procedure in one place: (1) 60 simulated contract cases, (2) 60 real format cases, (3) scoreboard on the same 20 cases, 3 repetitions, paired, accept if code-checkable metrics (format pass, quotes verified, math match) drop by at most 5 points, judge scores advisory, (4) canary on one agent for 48 h. Nightly canary = 5 fixed cases with code assertions only, alert after 2 consecutive failures; store provider, model, api_calls and tokens per run, and say plainly that silent swaps are detected only by the canary.
- Proving test: a degraded fake model (drops 20% of quotes) must fail the gate in at least 90% of 20 trials; an identical model must pass in at least 90%.
- Phase: 4.

### C-18 · the 👍/👎 loop and "exemplo de ouro" can teach errors at scale · medium

Resolve L261 versus L355 in favour of L355.
- Proving test: marking a delivery with a planted false quote as an example is refused; an example older than 90 days is not injected.
- Phase: 3.

### C-19 · Codex as "segundo executor": not locked down, different contract, different login · medium
- Scenario: `codex exec --output-schema FILE` sends `text.format = {type: json_schema, strict: true}` and does no client-side validation (a non-conforming mock reply still exits 0: exec/tests/suite/output_schema.rs:7-58; an unreadable or invalid schema file prints to stderr and exits 1: exec/src/lib.rs:2214-2237). - Fix (cut scope): Codex is not part of Fases 0 to 3. The doc says it enters in Fase 4 only after tests 3, 5 and the quote proof pass with it, running the same `helena_web` server, `--ignore-user-config --ignore-rules`, `--sandbox read-only`, an empty cwd and its own login.
